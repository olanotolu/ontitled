## Executive Summary

Ship from Thesean is real, well-executed, and represents the state-of-the-art in inference-time optimization. They cut LLM costs 50% while maintaining capability and behavioral equivalence. They have a quality SLA. They have traction with companies like Kilo and Baz.

**And they are optimizing the wrong layer.**

Ship optimizes **INPUT** — how to execute a request cheaper. Themis optimizes **OUTPUT** — what was actually achieved. This is not a subtle distinction. It is a fundamental architectural asymmetry that allows Themis to commoditize Ship and every other input-layer optimizer.

The inference optimization space is commoditizing fast. RouteLLM already achieves 85% cost savings. Not Diamond, Martian, LiteLLM, MindStudio, MESS+, AgentGate, and AutoClaw are all racing to the bottom on token pricing. The input layer is becoming a feature, not a platform.

**Themis operates at the output layer.** While everyone else fights over who can run a request cheapest, Themis answers the question that actually matters: "Was the work actually done?"

This brief explains how Themis achieves structural dominance over the entire AI execution stack — including Ship and every other input optimizer.

## 1. The Landscape Reality Check

### Ship from Thesean: The Validation

Ship proves that dynamic routing works. Their July 2026 launch demonstrates:

- **50% cost reduction** vs. reference models
- **Capability equivalence:** If the reference model solves it, Ship solves it
- **Behavioral equivalence:** Same output distribution, no prompt changes needed
- **Quality SLA:** Contractual guarantee on intelligence grade
- **Traction:** Processing trillions of tokens for customers like Kilo Code and Baz

Their technical approach is sound:
- Inference-time optimization (JIT-like compilation for LLMs)
- Dynamic method selection (models, cascades, ensembles)
- Reference-relative quality measurement
- Runtime information enables optimizations impossible at training time

**The problem:** Ship has hit a ceiling they cannot break through.

### The Input Layer Commoditization

The inference optimization space is crowded and converging:

| Platform | Cost Savings | Mechanism | Status |
|----------|--------------|-----------|--------|
| **Ship** | 50% | Inference-time JIT optimization | Live, July 2026 |
| **RouteLLM** | 85% | Preference-based routing | Open source, 618 citations |

| **AutoClaw** | 70% | Smart routing | Live |

The race to the bottom is already happening. RouteLLM's 85% savings sets a new baseline. Ship's 50% is table stakes. Everyone is optimizing the same thing: **cost per token**.

### Why Winning at the Compute Layer Is a Trap

The input-layer optimizers face structural constraints:

1. **Diminishing returns:** You can only optimize token cost so far before hitting hardware limits
2. **Commoditization:** Every technique (routing, cascading, speculative decoding) becomes open source within months
3. **Feature, not platform:** Input optimization is a capability, not a business model
4. **No data moat:** Request logs are less valuable than outcome data
5. **Vendor squeeze:** As model providers get more efficient, middleware margins compress

Ship's ceiling is the cost of raw compute plus their optimization margin. That's it. They can never escape the token economics trap.

Themis doesn't compete for AI compute dollars. It competes for labor dollars. The TAM is 100x larger.

Themis has ground truth. Dike verification checks actual systems of record:
- Was the ticket actually resolved?

This ground truth is:

## 3. How Themis Kills Ship

### The Integration Play

**Themis can USE Ship.** Ship becomes a supplier, not a competitor.

When Themis routes a UPX contract, it can select Ship as the execution method. Ship's 50% cost savings flow through to Themis's outcome pricing. Themis captures the value; Ship captures a supplier margin.

The integration hierarchy:
```
Enterprise Request
    ↓
Themis (outcome pricing, verification, settlement)
    ↓
Input Optimizers (Ship, RouteLLM, Martian, etc.)
    ↓
Models (Claude, GPT, DeepSeek, etc.)
    ↓
Compute (Ornn, cloud providers, etc.)
```

Themis commoditizes the commoditizers. Every input optimizer becomes a fungible execution method. Themis arbitrages across all of them.

### Ship's Ceiling vs. Themis's Floor

**Ship's ceiling:** Best execution for a given request. They can route to the cheapest model that maintains quality. They can optimize inference. They can cascade and ensemble. But they cannot answer: "Was the work actually done?"

**Themis's floor:** Verified outcome settlement. Even with zero routing optimization — even using the most expensive model every time — Themis provides value by verifying outcomes and settling payment. Routing optimization is incremental; verification is foundational.

Ship cannot move up the stack without fundamentally changing their architecture. They optimize requests; Themis verifies outcomes. These are different businesses.

### The Data Flywheel Asymmetry

**Ship's data:** Request features, prompt characteristics, model responses. This data improves routing decisions — but only routing decisions. It tells them which model to use for a given request type.

**Themis's data:** Verified outcomes, actual business results, state changes in systems of record. This data improves:
1. Routing decisions (which execution path delivers outcomes cheapest)
2. Pricing accuracy (what outcomes actually cost to deliver)
3. Risk models (which vendors/agents are reliable)
4. Contract design (what SLAs are achievable)

Outcome data is more valuable than request data. It's also harder to replicate. You need verification infrastructure, enterprise integrations, and trust. Ship has none of these.

### The Business Model Kill Shot

| Dimension | Ship | Themis |
|-----------|------|--------|
| **Revenue model** | % of compute savings | % of verified outcome value |
| **Revenue ceiling** | Capped by compute spend | Uncapped (scales with labor market) |
| **Growth driver** | Cost reduction | Value creation |
| **Customer stickiness** | Switching cost (API change) | Network effects (data moat) |
| **Competitive defense** | Algorithmic (replicable) | Structural (trust position) |

Ship charges for optimization. Their revenue is a percentage of compute savings. If AI gets 10x cheaper, Ship's revenue collapses.

Themis charges for outcomes. Their revenue is a percentage of verified value delivered. If AI gets 10x cheaper, Themis's volume increases (more tasks become economical) and margins expand.

**Ship is a cost center play. Themis is a value creation play.**

## 5. Technical Superiority Vectors

### How Themis Routes Better Than Ship

**Ship routes based on request features:**
- Prompt analysis
- Expected complexity
- Historical model performance on similar requests
- Real-time latency/cost tradeoffs

**Themis routes based on outcome predictions:**
- Verified historical success rates by domain
- Actual cost-per-outcome by execution path
- Vendor reliability scores (from verification data)
- Risk-adjusted pricing for complex tasks

**Example: Customer support ticket**

Ship's approach:
1. Analyze prompt complexity
2. Route to cheapest model that can handle it
3. Hope the response resolves the ticket
4. Log the request for future routing

Themis's approach:
1. Classify ticket type (UPX-CX-RES-US-L2)
2. Check historical data: Claude 5 resolves 94% of L2 tickets, DeepSeek resolves 89%, but DeepSeek costs 60% less
3. Route to DeepSeek (risk-adjusted expected value is higher)
4. Dike verifies: ticket marked resolved, no reopen within 72h, no human intervention
5. Log verified outcome to improve future routing

Ship optimizes for cost-per-token. Themis optimizes for cost-per-outcome. These can diverge significantly:
- A cheap model might resolve 70% of tickets (high cost per outcome due to reopens)
- An expensive model might resolve 95% of tickets (lower cost per outcome)

Ship picks the cheap model because it optimizes tokens. Themis picks the expensive model because it optimizes verified outcomes.

### The Verification Advantage

Dike verification creates ground truth that improves Themis routing. Ship has no ground truth loop — they're optimizing against benchmarks.

**The feedback loop:**

```
Themis Route → Model Execution → Dike Verify → Outcome Data → Improved Routing
                    ↑_______________________________________________|
```

Every transaction makes Themis smarter. Ship stays static relative to its training data.

**Why benchmarks fail:**

- Benchmarks measure capability, not completion

**Why verification succeeds:**
- Enterprise systems of record don't lie

## 6. The Kill Shot — Business Model Asymmetry

### Revenue Model Comparison

**Ship:**
- Charge: Percentage of compute savings (e.g., 20% of 50% savings = 10% of original compute cost)
- If customer spends $100 on tokens, Ship saves them $50, keeps $10, customer pays $60 total
- Revenue capped by compute spend
- Revenue DECREASES as compute gets cheaper

**Themis:**
- Charge: Percentage of verified outcome value (e.g., 10% of outcome value)
- If a support resolution is worth $5 to the enterprise, Themis keeps $0.50
- Revenue scales with AI adoption (more outcomes = more settlement volume)
- Revenue INCREASES as compute gets cheaper (more tasks become economical)

### The Jevons Paradox Play

As AI gets cheaper, usage explodes. This is Jevons Paradox: when resource efficiency increases, consumption increases even more.

**Ship's problem:** If compute gets 10x cheaper, token spend might only 2x (efficiency gains offset by usage growth). Ship's revenue is tied to token spend. Their growth is capped.

**Themis's opportunity:** If compute gets 10x cheaper, AI tasks that were uneconomical become viable. The volume of AI work explodes. Themis's revenue is tied to outcome volume. Their growth accelerates.

### The Commoditization Defense

Input optimization is inherently commoditizable:
- RouteLLM is open source
- LiteLLM is open source
- Academic papers publish routing algorithms
- Cloud providers will add routing as a feature

Ship's only defense is execution speed and customer relationships. That's weak against well-funded competitors.

Outcome verification is NOT commoditizable:
- Requires enterprise trust (takes years to build)
- Requires system integrations (expensive, time-consuming)
- Requires settlement infrastructure (financial licensing, compliance)
- Creates network effects (more data = better routing = more customers)

**Themis commoditizes Ship. Ship cannot commoditize Themis.**

**Their position:** Payment and metering infrastructure for AI agents. Tamper-proof logs. Cryptographic signing.

**The gap:** They notarize vendor-reported outcomes, not independently verified outcomes.

**Defense:**
- Nevermined settles what vendors claim; Themis settles what actually happened

**The asymmetry:** Nevermined needs Themis; Themis doesn't need Nevermined.

### Against Ship/RouteLLM/Martian/etc.

**Their position:** Optimize input execution. Route to cheapest model. Reduce token costs.

**The gap:** They optimize requests; Themis verifies outcomes.

**Defense:**
- Themis can use them all as suppliers
- They cannot become Themis without building verification infrastructure, enterprise trust, and settlement systems
- The output layer commoditizes the input layer, not vice versa

**The asymmetry:** Themis arbitrages across all optimizers. They compete with each other; Themis aggregates them.

### Against ServiceNow/Zendesk/Intercom
